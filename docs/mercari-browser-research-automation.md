# メルカリ・ブラウザリサーチ自動化

## 目的

Apps Script の `UrlFetchApp` では取得できない、JavaScript 描画後のメルカリ検索結果を
Codex のブラウザで取得し、Google Sheets の `リサーチ管理表` に同期する。

## 対象

- スプレッドシート ID: `1_jGREsciVE4SaljTl3tedgsDmODRF0SvvnWJSqfbr5o`
- シート: `リサーチ管理表`
- 注文番号: B列の `注文番号：xxx-xxxxxxx-xxxxxxx`
- 売上金上限: C列
- 検索ワード: D列
- リサーチ状況: E列
- メルカリ候補: H列
- 最終リサーチ日時: L列
- 確認メモ: M列

## 1回の処理範囲

1. 先頭25行だけを読んではいけない。最終データ行までの A:M を100行以下の範囲に分けて読み、全行から処理対象を選ぶ。
2. 読み取り後、非表示行、購入済み、削除済み、重複注文番号を対象外にしてから、L列が空、または最終確認が最も古い可視行を優先する。
3. 1回に実際にリサーチする行は最大25行とする。対象外行は25行の処理枠を消費しない。
4. 非表示行を理由に実行全体を停止してはいけない。非表示行はスキップし、次の可視対象行へ進む。同じスキップ理由をM列へ毎時上書きしない。
5. 同じ注文番号の行が複数ある場合はその注文だけ自動追記を停止し、他の正常な注文の処理を継続する。
6. 実行結果には、読み取った全データ行数、対象外件数、実リサーチ件数、最小・最大処理行番号を記録する。最大処理行番号が先頭読取範囲の末尾に固定された場合は選定異常として扱う。

## 検索

商品名から装飾語を除き、次の検索語を最大10個作る。媒体・巻数が分かる場合は、
それらを1つにまとめた高精度検索語を最優先にする。

1. 作品名 + DVD/Blu-ray + 全N巻 + レンタル（全巻注文）
2. 作品名 + DVD/Blu-ray + レンタル落ち（単巻注文）
3. 作品名 + 全N巻 + DVD/Blu-ray
4. 作品名
5. 作品名 + DVD または Blu-ray
6. 作品名 + レンタル
7. 作品名 + 全N巻
8. 作品名 + 全巻
9. 作品名 + 中古
10. 作品名 + シーズン・年・版などの識別語

作品名の照合では、全角・半角空白の有無を無視する。たとえば
`帰ってきたあぶない刑事` と `帰ってきた あぶない刑事` は同一作品名として扱う。

各検索語について、次のURLをブラウザで開く。

`https://jp.mercari.com/search?keyword=<検索語>&price_max=<売上金上限>`

DOM に描画された `/item/` と `/shops/product/` の両方のリンクから商品名、価格、URL、販売状態を取得する。
メルカリShopsを除外してはいけない。URLの許可ポリシーで商品ページへの直接遷移が拒否される場合は、
検索結果DOM内の該当リンクをクリックして同一タブで商品ページを開き、戻る操作で検索結果へ復帰する。
収集済みURLへ `goto` を繰り返す方法だけに依存してはいけない。
各検索語で販売中候補を最大60件、または3ページ分まで確認する。最初の24件だけで
打ち切ってはいけない。フィギュア・ゲーム・本・Blu-ray等の除外品が多い作品ほど、
媒体・巻数・レンタルを含む高精度検索語を先に実行する。

検索ページがHTTP 200でも `/item/` と `/shops/product/` のリンクがともに0件で、ゼロ件表示の明示もない場合は、
「候補0件」と判定してはいけない。JavaScript描画失敗またはアクセス制限として扱い、
同じ検索語を空白除去版と媒体付き版で1回ずつ再試行する。それでも取得できない場合は
書き込みを止め、M列へ `メルカリDOM取得失敗` と検索URLを記録する。

メルカリDOMを取得できない場合の発見補助として、Web検索で
`site:jp.mercari.com/item/ <作品名> <DVD/Blu-ray> <全N巻>` を1回実行してよい。
ただしWeb検索結果だけでは候補確定せず、必ずメルカリ商品ページで価格・販売中・媒体・
巻数を再確認する。再確認できないURLはH列へ追加せず、M列へ要確認として残す。

## DVD・Blu-ray判定

### 必須条件

- DVD注文: 候補名または商品詳細に `DVD`、`レンタル落ち`、`レンタルアップ`のいずれかがある。
- Blu-ray注文: 候補名または商品詳細に `Blu-ray`、`ブルーレイ`、`BD`のいずれかがある。
- 全N巻注文: 候補が同じN巻の全巻セットである。
- 単巻注文: 同一作品であり、別シーズン・別作品・続編ではない。
- 価格が1円以上、C列の上限以下である。
- 販売中である。売り切れ、公開停止、削除済みは除外する。

### 即時除外

本、書籍、雑誌、漫画、コミック、ムック、写真集、台本、脚本、パンフレット、
プレスシート、ポスター、チラシ、フライヤー、チケット、半券、前売券、入場券、
カード、シール、ステッカー、カレンダー、ポストカード、ジャケットのみ、
ケースのみ、特典のみ、ディスクなし、CD、VHS、ビデオ、LD、レーザーディスク、
ゲーム、Blu-ray注文に対するDVDのみ、DVD注文に対するBlu-rayのみ。

`全N巻` だけを媒体証拠として扱ってはいけない。

## 書き込み

候補はH列に既存内容を残したまま、URL単位で重複を除いて追記する。

```text
商品名
価格円｜状態
https://jp.mercari.com/item/...
```

- 候補が1件以上: E列を `候補あり`
- 候補が0件: 既存の `候補あり` を消さない。M列に確認日時と0件理由を追記
- L列: 商品ページまで検証して検索が正常完了した行だけ、実行日を `yyyy/MM/dd` で記録
- DOM取得失敗、URLポリシー、CAPTCHA、ログイン要求、アクセス制限などで未完了の場合はL列を更新しない。M列へ失敗段階とURLを残し、次回再試行対象にする
- 同じURLを再追記しない
- H列以外のサイト列は変更しない
- セルの書式、入力規則、数式を変更しない

## 検証

書き込み後に対象の B、C、E、H、L、M 列を再取得し、次を確認する。

- 注文番号と書き込み行が一致
- 上限超過がない
- 除外品がない
- URL重複がない
- 既存候補が失われていない
- 空白有無だけが異なる同一作品を誤って除外していない
- 検索結果の先頭24件より後ろにある適合候補を確認した

1件でも検証に失敗した場合、その行への書き込みを中止しM列へ理由を残す。
